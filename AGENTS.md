# Project Rules

These rules apply throughout this repository and guide its long-term maintenance with Codex. The user's latest explicit instruction always takes priority over general rules in this document.

## Purpose and Career Positioning

- This repository contains a professional personal portfolio website for graduate recruitment, intended for use as a personal homepage link on a graduate recruitment CV.
- The website is intended primarily for Project Management, Project Coordination, Management Trainee, and related business-facing roles.
- Emphasize project ownership, communication, coordination, leadership, structured problem solving, execution, and delivery.
- Technical, academic, and research experiences may support these capabilities, but must not define the website as a research or academic portfolio.
- Treat activities, leadership, competitions, volunteering, team projects, internships, and future professional experiences as important career evidence.
- When presenting technical or research experiences, emphasize transferable capabilities: ownership, planning, coordination, communication, presentation, problem solving, execution, and results.
- Do not make laboratory techniques, academic research details, publications, or technical terminology the dominant visual focus of the homepage.
- Do not copy the CV line by line. Keep content concise, recruiter-friendly, and easy to scan.

## Technology and Hosting

- Use HTML, CSS, and vanilla JavaScript only.
- Do not introduce React, Vue, Next.js, Node.js, npm, or other frameworks unless explicitly requested.
- Keep the website compatible with GitHub Pages.
- The repository name is `Kelly_Shixinyao.github.io`, which is not the standard `username.github.io` user-site repository name. Therefore, use relative paths throughout the website.
- Do not use root-relative asset paths such as `/style.css`, `/script.js`, or `/assets/...`.
- Avoid unnecessary dependencies and external libraries.
- Keep the code structure simple, readable, and suitable for a programming beginner to maintain with Codex.

## Content Structure

Design the website to support these main sections:

- Home
- Profile
- Selected Experience
- Selected Projects
- Activities & Leadership
- Skills
- Highlights
- Education
- Contact

Keep the structure flexible so that new internships, work experiences, projects, activities, awards, and leadership experiences can be added later. Whenever practical, keep personal content separate from layout and styling so that future content updates require minimal code changes.

## Visual Design and Interaction

- Make the website professional, polished, modern, premium, and suitable as a personal portfolio link on a graduate recruitment CV.
- Aim for a high-end corporate portfolio or modern product website rather than a traditional résumé template, academic homepage, laboratory website, or programmer portfolio.
- Prioritize clear information hierarchy, generous whitespace, strong typography, balanced spacing, and refined alignment.
- Use a restrained, professional palette such as white, off-white, charcoal, dark navy, and soft gray, with one restrained accent color.
- Establish clear typography hierarchy for names, section headings, body text, dates, tags, and supporting information.
- Use cards, timelines, tags, dividers, subtle borders, and subtle shadows when they improve readability. Avoid making every section a separate boxed card.
- Make the homepage visually impressive at first glance while keeping it easy for recruiters to scan within 20–30 seconds.
- Use subtle, purposeful animation only, such as gentle fade-in effects, hover transitions, smooth scrolling, or small interaction feedback.
- Avoid particle effects, complex 3D scenes, neon or cyberpunk aesthetics, excessive gradients, heavy animation, complicated loading screens, and distracting effects.
- Ensure a polished appearance on both desktop and mobile devices.

## Privacy and Downloads

- Do not publish or link academic transcripts.
- Do not expose private or unnecessary personal information.
- Do not add home addresses, identity documents, or other sensitive information.
- Do not add personal phone numbers to the public website unless explicitly requested.
- A CV download may be added later, but it must be a CV-only file and must not contain the academic transcript.

## Maintenance Workflow

- The website owner is a programming beginner. Prefer small, targeted, reversible changes.
- Do not redesign the whole website when only a small content update is requested.
- Do not delete existing content unless explicitly requested.
- Do not change the technology stack unless explicitly requested.
- When adding experiences, awards, projects, or activities, preserve the existing design system and layout.
- Whenever possible, update content data rather than rewriting major parts of the website.
- Before making a major structural or visual change, briefly explain in Chinese what files will be changed and why.
